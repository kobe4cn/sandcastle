# 受保护路径挡自动合并

## 背景

有些文件改错了代价很高、又很难靠门槛和评审发现：CI 配置（`.github/`）、数据库迁移、部署脚本、权限配置等。评审只在 implement / 打回之后跑一次，门槛失败后的 fix 和 rebase 补救里 agent 解冲突的改动虽然有复审（#70、#71），复审看的也只是代码对不对，不会因为「这类文件就该人看」而拦下。项目需要一条与代码好坏无关、按路径一刀切的规则：改到这些文件就留给人合并（#57）。

## 决定

项目配置加可选的 `protectedPaths: RegExp[]`，不写时为 `[]`，行为完全不变：

- 规则是正则，匹配相对仓库根、不带前导 `/` 的路径，和 `git diff --name-only` 的输出一致。
- 受保护路径是**合并关卡**，与评审无关：检查在 land（门槛、复审、fix HEAD 检查之后，验收说明之前）对票的最终 diff（`BASE_REF...HEAD`，review / 打回 / fix 之后取）做；有文件命中就留 PR（`sandcastle:pr-open`），评论逐条列出「文件 — 命中的规则」（规则写 `String(re)`，每个文件只报第一条命中的）。
- fix 和 rebase 解冲突都不经评审，所以检查放在 land 和 rebase push 前，而不是评审里：rebase 补救中起过解冲突 agent（冲突或完整性链断）且门槛通过时，push 前在沙箱重取 diff 再查一次，命中就不 push、由调用方留 PR。干净 rebase 不起 agent，diff 的文件集合没变，land 已查过，不再查。
- 配了规则但取不到 diff 时按命中处理（fail-closed），评论说明取不到 diff、无法判断。
- 外部 PR 和 reviewer 没给 `merge` 的票本来就留 PR，不另查。
- lockfile 不进 onboard 默认值（见 #75），需要的项目自己加。

## 考虑过的方案

- **把受保护路径交给 reviewer 判断（写进提示词）**：否决。fix 和 rebase 解冲突不经评审，且 agent 的判断不稳定；路径规则应当由脚本确定性地执行。
- **用 glob 而不是正则**：否决。配置里已有 `browser.pagePaths` 用正则，保持一致；配置是宿主机动态 import 的 TS 文件，正则不用序列化。
- **取不到 diff 时放行**：否决。配了规则说明项目在意这些路径，取不到就无法保证没改到，和复审没结论按不通过一致（fail-closed）。
- **票正文里显式允许改受保护路径**：另开 #76，本决定不含。

## 后果

- 配了 `protectedPaths` 的项目，改到这些路径的票全部留 PR 等人合并，自动合并率会下降；规则要写窄。
- 取不到 diff（沙箱异常）时也会留 PR，比放行多一些人工。
- rebase 补救里多一次 `git diff`，只在起过 agent 时跑。
