# 补项目知识只在 onboard 阶段做

## 背景

流水线里的每个 agent 都是全新会话，只靠写下来的项目知识了解项目。缺意图类信息时，prep 和 implement 只能猜；猜错了，测试门槛也拦不住，因为测试也是 agent 自己写的。

## 决定

补项目知识只在人参与的 onboard 阶段做，靠缺口清单把需要人回答的规范类和意图类问题列出来、逐条补完。

无人值守的流水线里只做兜底：prep 发现缺意图类信息时打 `sandcastle:stuck`，评论里写明缺什么、该写进哪份文档。

## 考虑过的方案

- **在流水线里让 AI 自己补文档**：否决。意图推不出来，AI 补等于猜；而测试也是 AI 写的，拦不住猜错的意图。
- **新增 `needs-info` 标签**：否决。已有的 `sandcastle:stuck` 就表示「需要人介入」，再加一个标签只会多一种状态，人要看的地方也变多。
- **把缺口清单注入提示词**：否决。清单里「红线未定」这类条目会让所有票都被卡住。
- **doctor 用启发式检查（比如「没有术语表就报错」）并让它失败**：否决。判断「不需要」的权力在人，所以这类检查只 warn、不 fail。

## 后果

- 只涉及事实的票，没有文档也能做；涉及意图的票会 stuck，等人补。
- 产出质量取决于写下来的意图有多少。
- PROJECT.md 改完马上生效；术语表和 ADR 要推到 main 之后，沙箱里的 agent 才读得到，因为沙箱从 `origin/main` 建 worktree。
