5. 用 Write 写 {{WRITABLE}}（只许改这些文件）。

## PROJECT.md 的格式

只能用下面模板里的 `## ` 标题，不认识的标题会让流水线启动失败；「概况」「开发命令」「测试」「提交」必填，其余确实没有就整节删掉。模板的注释写了每节进哪些阶段、该写什么：

```markdown
{{TEMPLATE}}
```

写法要求：

- 每节会原样注入 agent 的提示词，写成「给 agent 的指令」：短、具体、可执行；给路径、命令、函数名，不写空话（「保持代码整洁」这类不要）。
- 只写本项目特有的。通用规则（先写测试、小步提交、不要猜）流水线的模板里已经有了。
- 命令用普通反引号；不要写 `!` 紧跟反引号的写法（那是提示词里执行命令的语法，会报错）。HTML 注释不进提示词，草稿里的注释写完后删掉。
- 「浏览器验收」：项目有网页界面时必须走完这一步，信息按顺序取：
  1. 先读项目已有资料：事实里的 `browserHints`（脚本按关键字找到的，不全），以及旧的 `.sandcastle/*prompt*.md` / `.sandcastle/prompts/`、README / CLAUDE.md / AGENTS.md / CONTRIBUTING、测试目录的说明、docs 里提到 playwright、ego-browser、e2e、截图、登录方式、dev server 的章节，`scripts/` 里建种子或验收数据的脚本（看它的用法注释和要的参数）。
  2. 能拼出四步就写这一节：准备数据（哪个脚本、什么参数）、后台起服务并等 curl 通（命令、端口）、`playwright-cli` 登录（地址离开登录页才算成功）、查日志。资料里写的是宿主机工具（如 ego-browser、本机浏览器）的，换成沙箱里的 `playwright-cli`；宿主机上的路径、端口、账号按沙箱的情况改写。dev server 在沙箱里读的变量（数据库、会话密钥等）都要出现在 config 的 `isolation.env` 里，库要用 `withDbSuffix` 分出独立的；缺的话在最后的输出里写明。
  3. 拼不全就不写这一节（改页面的票会留给人看），把缺的信息作为具体问题写进缺口清单（见下面「缺口清单」）：dev server 启动命令与端口、验收数据怎么建、登录方式与账号、dev server 需要的环境变量。
  完整说明见 sandpipe 的 config 文档「浏览器验收」一节。
- 「必须停下」写碰到就该交给人的红线（多租户隔离、计费、对外协议、数据迁移的不可逆操作……），没有就删掉。
- 不确定的不要编：按下面「缺口清单」一节记下来。
- 全文 60–120 行为宜，不超过 150 行。
